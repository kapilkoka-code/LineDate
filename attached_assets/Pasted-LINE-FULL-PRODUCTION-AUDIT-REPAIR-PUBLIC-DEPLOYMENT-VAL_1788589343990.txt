This is NOT a feature-development step.

Do NOT add new product features unless they are necessary to repair an existing feature.

3. CAMERA/FIND — PRIORITY #1

The camera currently appears not to be working.

Investigate this deeply.

Do not simply assume this is a permission issue.

Check the entire camera chain:

Browser

Check:

* navigator.mediaDevices
* getUserMedia
* secure context requirements
* HTTPS
* camera permission state
* browser compatibility
* iOS Safari behavior
* Android Chrome behavior

Stream

Check:

* Whether getUserMedia() is actually called
* Whether the promise resolves
* Whether it rejects
* Exact error name
* Whether video tracks are returned
* Whether tracks are immediately stopped
* Whether srcObject is assigned
* Whether video.play() succeeds
* Whether the video element is actually visible
* Whether CSS is hiding the camera
* Whether an overlay is covering it
* Whether lifecycle cleanup stops the stream prematurely

React lifecycle

Look for:

* Race conditions
* Component unmount
* State transitions
* Stale refs
* Cleanup firing too early
* Permission requests happening outside user gestures
* Camera initialization occurring after another lifecycle transition

iOS

Pay particular attention to:

* playsInline
* muted
* autoPlay
* user gesture requirements
* Safari camera permission behavior
* orientation permission
* page visibility
* camera stream lifecycle

Production

Compare development and production behavior.

Check whether:

* Vite bundling changes anything
* Environment variables affect camera initialization
* CSP/security headers interfere
* HTTPS is actually active
* iframe/embed restrictions exist
* Replit deployment headers interfere

Required result

The FIND camera must actually display the rear/environment-facing camera on supported devices.

If camera access is genuinely unavailable, the application must display a clear and accurate fallback.

Never show a blank black screen while implying FIND is active.
